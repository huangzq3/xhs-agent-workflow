# 小红书发布

发布是外部状态变更。只接受明确路径和明确账号，不使用“今天最新”“上一个目录”等推断。

面向内容负责人的发布问题和结果说明必须遵守 [人工交互与审阅规范](../xhs-workflow/references/human-interface.md)。不得要求其理解内部阶段号、状态码或策略枚举；发布预览和审计只交付中文 HTML。

## 前置条件

1. 内部要求明确的本轮任务、账号运营策略、可以发布或已排期的库存项、已定稿内容和目标账号。
2. 校验库存引用、内容定稿确认、素材权利和账号运营策略确认仍有效；不得跳过库存层直接查找“最新内容”。
3. 读取 `authenticated_platform_control` 与可选的 `scheduled_execution` 能力快照。只调用已展示且已授权的能力；不得根据 Agent 品牌猜测是否支持定时任务。
4. 核对当前实际发布界面的登录账号与 `target_account_id`。不一致时停止。
5. 登录、验证码、实名验证和账号切换始终由账号负责人完成。

## 工作流

1. 按 [references/publish-checklist.md](references/publish-checklist.md) 检查内容、素材、事实、平台限制和账号。
2. 按 [references/publishing-policy.md](references/publishing-policy.md) 运行规则检查并同步到库存项和发布记录。“当前规则不允许”时停止；“需要人工判断”时在发布前确认中用业务语言说明原因。
3. 创建内部发布记录，绑定策略、库存项和内容，并标记为待人工确认。
4. 生成最终预览，展示标题、正文、标签、素材顺序、可见范围、目标账号、策略结果和内容 hash。选择定时发布时，还必须展示定时时间、时区、最晚允许执行时间和实际执行方式。
5. 请账号负责人完成“发布前确认”。确认必须绑定当前预览；沉默不视为同意。
6. 立即发布按当前流程执行；定时发布按 [references/scheduled-publishing.md](references/scheduled-publishing.md) 选择“平台原生定时、运行工具到点唤醒、人工到点交接”之一。无法证明某种方式可用时不得选择该方式。
7. 每次发布前确认只允许一次提交尝试。运行工具到点唤醒或人工到点交接时，必须在允许时间窗口内重新检查当前账号、内容版本和发布规则；错过最晚时间后不得自动补发。
8. 平台原生定时提交成功时保存可核对的排期凭据；不能把“已排期”写成“已上线”。
9. 平台明确返回远端 ID 或可验证 URL 后，记录平台确认的实际上线时间及核对依据，再写入 `published`。计划时间、排期提交时间和运行工具开始执行时间都不能代替实际上线时间。
10. 平台明确拒绝且未创建内容时写入 `failed`。
11. 超时、页面崩溃、返回模糊或无法判断是否已创建时，对人工显示“发布结果待核对”，停止自动重试。
12. 由账号负责人检查创作中心后，人工确认“已发布”或“发布失败”；只有在实际上线时间已核对后，才推进库存项并生成配置化复盘周期。

## 禁止事项

- 未获发布前确认不点击最终发布。
- 不绕过登录、验证码、风控或平台限制。
- 不自动修改或删除远端内容；发布后动作必须有单独的人工决定记录。
- 不在失败后直接重试；先检查是否重复发布并重新批准。
- 不把本地预览成功当作平台发布成功。
- 不把设置了定时任务当作发布成功，也不在错过允许时间后静默补发。
- 不用计划发布时间推算内容生命周期；复盘统一从实际上线时间起算。
- 不通过裁剪水印宣称版权合规。

发布成功后登记 publication artifact 并推进 inventory_item；后续复盘必须引用其远端 ID，而不是从文本中提取 URL。
