# 小红书实验迭代

迭代产物是实验计划，不是自动塞回选题池的泛化建议。

面向内容负责人的实验说明和确认问题遵守 [人工交互与审阅规范](../xhs-workflow/references/human-interface.md)，使用业务语言并只交付中文 HTML，不展示内部分类值或原始 JSON。

## 前置条件

1. 内部要求明确的复盘、本轮任务和账号。
2. 校验复盘引用的数据快照与内容均属于同一账号。
3. 校验对比样本使用核对后的实际上线时间，并具有相近的上线后观察时长；计划发布时间不同不能自动解释表现差异。
4. 复盘证据不足时可以提出探索性实验，但必须降低判断把握度，不把假设写成结论。
5. 定位实验读取复盘逐项假设结果、五路证据和受众市场镜像，遵守 [定位生长闭环](../xhs-workflow/references/positioning-loop.md)。

## 工作流

1. 读取数据直接支持的观察、可能原因、其他解释和建议行动。
2. 按 [references/diagnosis-topic-mapping.md](references/diagnosis-topic-mapping.md) 将干预归为：
   - `topic`：受众需求或主题选择；
   - `creative`：标题、开头、结构、视觉、口播；
   - `distribution`：SEO、发布时间、标签、发布方式；
   - `positioning`：具体账号的受众、价值主张、关系表达或内容支柱映射；
   - `strategy`：创作者方向、90 天主目标、商业去向、信任/内容引擎、记忆资产、生命周期、内容目标组合、库存、发布或测量策略。
3. 先选择实验方式：未知较多时使用 `exploration_probe`，围绕一个明确问题安排差异维度；定位相对稳定后的创意或分发优化使用 `controlled_optimization`，只设置一个主要独立变量并明确对照。
4. `creative` 或 `distribution` 问题不得改造成“教创作者提高留存/SEO”的账号选题。
5. `topic` 实验可以提出下一轮 topic seed，但其优先级低于内容负责人本轮明确输入。
6. 所有实验显式关联本轮要回应的定位假设，并定义需要采集的证据流、有效曝光规则和内容兑现规则。定位实验不得引用关联复盘没有评估的假设。
7. 账号定位实验只生成结构化定位修订建议；创作者方向和运营策略实验只生成策略修订建议。建议前必须先完成定位问题诊断，不把内容兑现不稳定或证据不足误判为定位/方向错误。不得直接修改账号定位或运营策略；接受结果后建立新版本并重新进行对应人工确认。
8. 定位修订建议必须说明保留、修订、退役或重新检验哪些假设，并给出昵称、简介、置顶内容、系列名称、评论回应或旧内容处理等必要迁移动作。
9. 写入内部实验记录并标记为待人工确认，运行核心辅助器校验。
10. 生成中文 HTML，展示实验方式、成本、预期信息增益、证据计划和风险，请内容负责人完成“迭代实验确认”。
11. 确认通过后登记到下一轮；实验完成前不得宣称改动有效。

## 输出

- 机器层：内部实验记录与后续结果审计。
- 人工层：中文 HTML 实验卡，展示探索或优化方式、关联定位假设、差异维度或唯一调整项、证据计划、观察时间、风险和停止条件。
- 最终回复只提供实验摘要和 HTML 路径。

字段说明见 [references/iterate-schema.md](references/iterate-schema.md)。
