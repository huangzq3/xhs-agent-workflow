# 复盘报告视图

报告必须从内部复盘记录确定性渲染，不得在展示层新增结论。面向内容负责人的正式报告固定为中文 HTML；不得用 JSON、Markdown、命令输出或字段表替代。

建议结构：

1. 账号、内容、实际上线时间、时间核对依据、观察窗口和数据完整性
2. 与适用基线的对比
3. 数据可以直接支持的观察
4. 内容是否按定位假设完整兑现，以及是否获得足以判断的有效曝光
5. 受众共鸣、内容兑现、平台分发、创作者适配和商业适配五条证据流
6. 受众如何用原话复述账号价值，及其与预设定位的偏差
7. 每条被本内容测试的定位假设：支持、反驳或暂无结论，并列出反证和其他可能解释
8. 信任表现与长尾表现
9. 需要人工确认的账号阶段和定位建议
10. 按选题、内容表达、发布分发、账号定位和运营策略分类的建议行动
11. 局限与下一次需要补采的数据
12. 待批准的探索型验证或受控优化候选

视觉规则：

- 明确区分绝对值、增量和比例。
- 图表标注样本数、窗口、分母和缺失值。
- 同时展示应采集时间、实际采集时间和上线后已观察时长；延期数据不得只沿用原计划窗口名称。
- 不用红绿颜色单独表达好坏。
- 不把低置信度推断放进“确定结论”。
- 内容兑现不足或有效曝光不足时，定位假设只能标记为暂无结论，不得写成受众无需求或定位失效。
- 五条证据流分开展示，避免把分发弱、表达弱或创作者不可持续误诊为账号定位错误。
- HTML 必须对平台文本、评论和链接转义。
- 顶部先展示当前结论、数据完整度、风险和下一步人工决定，再展示细节。
- 内部编号和校验指纹只能放在默认折叠的“追溯信息”区域。
- 页面不得出现内部阶段号、未经翻译的状态值、原始机器字段或原始 JSON。
- HTML 生成失败时明确标记报告交付失败，不得把机器文件直接发给内容负责人。
