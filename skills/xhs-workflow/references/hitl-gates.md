# 人工确认机制

人工参与不等于最后点一次确认。每次决定都必须提供足够背景、可退回修改、可暂停、可追溯，并使用内容负责人当前使用的语言。人工界面规范见 [human-interface.md](human-interface.md)。

## 内容负责人看到的确认步骤

| 确认步骤 | 需要审阅的内容 | 确认后允许的动作 |
|---|---|---|
| 启动与授权确认 | 当前工具能力、执行方式、目标账号、数据来源、登录状态和外部处理范围 | 启动本轮运营 |
| 账号运营策略确认 | 账号阶段、依据、内容目标、库存、发布与复盘规则 | 建立或修订账号定位 |
| 账号定位确认 | 身份、受众、差异化、表达边界、试运营假设和验证计划 | 使用该定位研究选题 |
| 选题确认 | 候选选题、证据强度、局限、优先级和风险 | 选择一个或多个选题创作 |
| 内容定稿确认 | 文案改动、事实表述、个人经历、素材权利、图片或视频 | 生成最终发布预览 |
| 发布前确认 | 目标账号、最终内容、素材顺序、时间、规则检查和例外 | 执行一次发布尝试 |
| 数据采集范围确认 | 短期窗口、信任指标、长尾时间点、人工评价、隐私和同步目标 | 采集平台数据 |
| 迭代实验确认 | 假设、唯一调整项、对比基线、观察时间、停止条件和账号影响 | 将实验投入下一轮 |

## 决定规则

- 只有自然人或由内容负责人明确指定的人工角色可以作出“确认通过”。
- HTML 审阅页展示当前版本、与上一版的差异、证据、风险和局限；内部校验指纹只放在折叠的追溯区域。
- 每次提供“确认通过、退回修改、暂不处理”三种可理解的选择；沉默不视为同意。
- 重新生成、改写、换图、改变素材顺序或改变数据范围后，受影响的人工确认自动失效。
- 启动、定稿、发布和数据采集时，必须明确展示外部数据处理、版权和隐私影响。
- 当前工具能力或实际数据处理边界发生变化时，启动与授权确认自动失效。
- 把“建议修改账号定位”和“同意修改账号定位”分开记录。
- 发布后的修改与删除是新的人工决定；发布前确认不授权未来任意修改或删除。
- 试运营时确认的是定位假设边界和验证计划，不得描述为“定位已经验证”。

## 发布结果不确定

无法确认平台是否已经创建内容时：

1. 对内容负责人显示“发布结果待核对”；
2. 立即停止自动重试；
3. 请求内容负责人检查小红书创作中心；
4. 由内容负责人明确选择“已发布”或“发布失败”；
5. 如需再次发布，重新生成预览并重新进行发布前确认。
