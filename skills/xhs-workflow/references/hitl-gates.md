# Human-in-the-loop 门禁

Human-in-the-loop 不等于“最后点一次确认”。人工决定必须获得足够上下文、可拒绝、可修改、可追溯，并能暂停流程。

| 门禁 | 人工审阅内容 | 批准后允许的动作 |
|---|---|---|
| G0 | 实际 Agent 能力快照、执行模式、账号身份、数据范围、登录态使用和外部处理范围 | 启动本轮工作流 |
| G1（战略） | 生命周期、证据、内容目标、库存/发布/测量策略 | 建立或修订 persona |
| G1（persona） | 定位事实、受众、边界；试运营假设和验证计划 | 用 persona 生成选题 |
| G2 | 选题证据、来源等级、局限、优先级 | 选择一个或多个选题创作 |
| G3 | 文案 diff、事实主张、个人经历、素材权利、敏感信息 | 生成发布预览 |
| G4 | 目标账号、最终内容、素材顺序、时间、策略检查与例外 | 执行一次发布尝试 |
| G5 | 短期窗口、信任指标、长尾检查点、人工量表、隐私与同步目标 | 采集平台指标 |
| G6 | 假设、变量、基线、窗口、停止条件、定位/战略影响 | 将实验投入下一轮 |

## 决定规则

- 只有自然人或由内容负责人明确指定的人工角色可以写入 `approved`。
- 展示批准对象的 artifact ID、版本、payload hash 和与上一版的差异。
- 提供 `approved`、`rejected`、`revoked` 三种决定；沉默不视为同意。
- 重新生成、改写或换图后使受影响的批准失效。
- 对 G0、G3、G4、G5 明确展示外部数据处理、版权和隐私影响。
- 运行时能力由 `unknown`、`unavailable` 变为 `available`，或实际 `capability_id` 变更时，原 G0 失效。
- 把“建议修改定位”和“批准修改定位”分开记录。
- 发布后的修改与删除是独立人工决定；G4 不授权未来任意修改或删除。
- 试运营 G1 批准假设边界和验证计划，不宣称 persona 已被验证。

## 发布不确定性

发布状态使用：

```text
draft -> review_required -> approved -> publishing
publishing -> published | failed | unknown
unknown -> published | failed   # 只能由人工核对远端页面后解决
failed -> review_required       # 修改或人工允许后再尝试
```

不得从 `unknown` 自动回到 `publishing`，避免重复发布。
