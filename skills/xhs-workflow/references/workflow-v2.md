# V2 流程与职责

## 1. 初始化

1. 选择唯一账号并创建 `account_id`。
2. 按运行时显式展示的能力建立快照，不假定 Agent 品牌、工具名称或安装目录。
3. 声明数据来源、允许使用的登录态和外部处理能力。
4. 创建 run manifest，由内容负责人审阅能力快照和数据范围后完成 G0。

## 2. 账号战略

1. 明确生命周期阶段、置信度、证据和替代解释。
2. 配置内容目标、发布规则、库存目标和短期/长尾测量计划；没有基线的数字留空。
3. 产出版本化 account_strategy，完成战略 G1。
4. 账号资料不被动态策略静默覆盖。

## 3. 定位

1. xhs-persona 只读取本轮明确输入和同账号资料。
2. 将竞品信息写入 provenance，不复制竞品表达。
3. trial 阶段使用 assumed persona、可证伪假设和验证计划。
4. 产出 persona JSON 和 Markdown 审阅视图。
5. 完成 persona G1；变更时建立新修订版。

## 4. 选题

1. 保留内容负责人给出的原始选题，不强行补齐数量。
2. 搜集可核对证据；证据不足时标成 hypothesis。
3. 按相关性、需求、证据强度、差异化和可执行性评分，不强制高低档分布。
4. 完成 G2 后，显式选择 `topic_id`。

## 5. 创作与库存

1. 读取已批准 persona 与 topic_report JSON。
2. 区分事实、观点、假设和个人经历；只使用已提供的个人经历。
3. 为每个素材保存来源、权利依据和哈希。
4. 需要生图时产生 `image_job` JSON，由当前 Agent 的已展示原生生图能力执行；缺失时降级为本地文字卡或人工交付。
5. 明确 acquisition、trust 或 tag_strengthening 目标；试运营记录内容序号。
6. 展示版本差异，完成 G3。
7. 建立 inventory_item，只有有效 G3 才能进入 ready/scheduled。

## 6. 发布

1. 按当前账号战略检查发布节奏，创建 publication JSON，绑定战略、库存项、内容和目标账号。
2. 生成包含策略结果的最终预览并完成 G4。
3. 如当前 Agent 有已授权的登录态平台操作能力，用该能力执行；否则由账号负责人手动提交并回填结果。
4. 每次批准只允许一次发布尝试。
5. 写入远端 ID/URL；不确定时进入 `unknown`。
6. 远端修改/删除需要新的人工决定；发布成功后按战略配置生成长尾检查点。

## 7. 采集与复盘

1. 完成 G5，明确短期窗口、信任指标、人工量表和长尾检查点。
2. 保存存量值与期间增量，不对存量快照求和。
3. 用账号自身历史分位数作为首选基线，行业数据只作辅助。
4. 把观察、因果假设和建议分开表达。
5. review 记录生命周期和 persona 验证建议，但不直接修改账号级 artifact。

## 8. 实验与迭代

1. 将问题归为 topic、creative、distribution、positioning 或 strategy。
2. 为每个建议定义假设、单一变量、目标指标、护栏、窗口和停止条件。
3. 完成 G6 后才把实验写入下一轮。
4. positioning 可提出 persona 修订，strategy 可提出 account_strategy 修订；二者均需要新 revision 和新的 G1。
