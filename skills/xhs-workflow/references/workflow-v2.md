# V2 流程与职责

## 1. 初始化

1. 选择唯一账号并创建 `account_id`。
2. 按运行时显式展示的能力建立快照，不假定 Agent 品牌、工具名称或安装目录。
3. 声明数据来源、允许使用的登录态和外部处理能力。
4. 创建内部任务记录，生成中文 HTML，由内容负责人完成“启动与授权确认”。

## 2. 账号战略

1. 明确生命周期阶段、置信度、证据和替代解释。
2. 配置内容目标、发布规则、库存目标和短期/长尾测量计划；没有基线的数字留空。
3. 产出版本化账号运营策略，完成“账号运营策略确认”。
4. 账号资料不被动态策略静默覆盖。

## 3. 定位

1. xhs-persona 只读取本轮明确输入和同账号资料。
2. 将竞品信息写入 provenance，不复制竞品表达。
3. 试运营阶段使用“试运营定位（待验证）”、可证伪假设和验证计划。
4. 产出内部账号定位记录和中文 HTML 审阅页。
5. 完成“账号定位确认”；变更时建立新版本。

## 4. 选题

1. 保留内容负责人给出的原始选题，不强行补齐数量。
2. 搜集可核对证据；证据不足时标成待验证假设。
3. 按相关性、需求、证据强度、差异化和可执行性评分，不强制高低档分布。
4. 完成“选题确认”后，在内部登记被选择的选题编号。

## 5. 创作与库存

1. 读取已确认的账号定位与选题内部记录。
2. 区分事实、观点、假设和个人经历；只使用已提供的个人经历。
3. 为每个素材保存来源、权利依据和哈希。
4. 需要生图时产生内部图片任务，由当前 Agent 的已展示原生生图能力执行；缺失时降级为本地文字卡或人工交付。
5. 明确“吸引新受众”“建立信任”或“强化账号标签”目标；试运营在内部记录内容序号。
6. 用中文 HTML 展示版本差异，完成“内容定稿确认”。
7. 建立内容库存项；只有有效的内容定稿确认才能进入可以发布或已排期状态。

## 6. 发布

1. 按当前账号运营策略检查发布节奏，创建内部发布记录，绑定策略、库存项、内容和目标账号。
2. 生成包含规则检查结果的中文 HTML 最终预览，并完成“发布前确认”。
3. 立即发布可直接执行；定时发布根据已证明的运行能力选择平台原生定时、运行工具到点唤醒或人工到点交接，并明确时区和最晚允许执行时间。
4. 平台原生定时提交后保存排期凭据；其他定时方式到点后重新检查账号、内容版本和发布规则。错过最晚时间后停止自动补发。
5. 每次批准只允许一次发布或排期尝试。
6. 只有平台内容真正可访问后才写入已发布，并同时记录实际上线时间及核对依据；计划时间和任务执行时间不能替代。
7. 不确定时对人工显示“发布结果待核对”。远端修改/删除需要新的人工决定。

## 7. 采集与复盘

1. 完成“数据采集范围确认”，明确从实际上线时间起算的短期窗口、信任指标、人工评价和长尾时间点。
2. 以上线时间为零点生成到期计划；周期未满不提前完成正式快照，延期采集保留应采集时间和实际采集时间。
3. 保存存量值与期间增量，不对存量快照求和。
4. 只比较上线后观察时长相近的样本，并用账号自身历史分位数作为首选基线；行业数据只作辅助。
5. 把观察、因果假设和建议分开表达。
6. 复盘记录账号阶段和定位验证建议，但不直接修改账号级记录。

## 8. 实验与迭代

1. 将问题归为选题、内容表达、发布分发、账号定位或运营策略。
2. 为每个建议定义假设、单一变量、目标指标、护栏、窗口和停止条件。
3. 完成“迭代实验确认”后才把实验写入下一轮。
4. 账号定位实验可提出定位修订，运营策略实验可提出策略修订；二者均需要建立新版本并重新进行相应人工确认。
