# 人工交互与审阅规范

本文件约束所有面向内容负责人的提问、状态说明、审批请求和报告。机器字段、内部状态码与命令参数仍可在内部文件和工具调用中使用，但不得原样变成人工界面。

## 不可违反的规则

1. 跟随内容负责人当前使用的语言；无法判断时使用简体中文。
2. 提问先说明业务背景、当前结论和影响，再提出一个可直接回答的问题。
3. 不要求内容负责人理解内部阶段号、字段名、状态码、文件结构、哈希或命令参数。
4. 不在对话、审批请求或交付说明中粘贴原始 JSON、NDJSON、Schema 或命令输出。
5. 人工审阅只交付安全转义的 HTML 页面；不把 Markdown 或 JSON 当作人工报告。
6. 每次人工确认必须提供“确认通过、退回修改、暂不处理”三种可理解的选择。沉默不算确认。
7. 如内容被改写、图片被替换、发布账号变化或数据范围变化，用业务语言说明原确认已失效以及需要重新确认的内容。
8. 只有内容负责人明确要求“查看技术数据”时，才可另行提供机器文件；该文件不得替代 HTML 审阅页。

## 提问模板

采用以下顺序：

1. **发生了什么**：一句话说明当前阶段与已完成内容。
2. **需要关注什么**：列出最多五项真正影响决定的信息。
3. **有什么风险或缺口**：明确缺失证据、外部数据处理、版权或发布不确定性。
4. **需要作出什么决定**：只提出当前能回答的一个问题。

错误示例：

> persona=assumed，是否批准 G1？

正确示例：

> 当前账号仍处于试运营阶段，这份定位是假设方案，尚未被数据验证。计划先用 6 篇差异化内容验证目标受众和内容方向。内容负责人是否同意按这份定位开始试运营？也可以退回修改或暂不处理。

错误示例：

> policy_check=needs_human，请批准 G4。

正确示例：

> 发布前检查发现同类选题距离上次发布不足账号设定的间隔。内容负责人是否仍要发布本篇？如继续，本次例外只授权一次发布尝试。

## HTML 审阅页

人工审阅页至少包含：

- 当前业务阶段和状态；
- 本次需要决定的事项；
- 与决定直接相关的内容、证据、风险和局限；
- 信息来源；
- 历史人工决定；
- 默认折叠的追溯信息。

内容定稿页还必须同时展示独立文章审计的结论、风险级别、尚未解决的问题与修订方向。不展示内部英文枚举或原始问题 JSON。审计结论为“需要内容负责人决定”时，页面要求记录具体取舍理由。

页面不得包含原始 JSON、代码块、内部字段表、英文状态机或未经翻译的阶段号。关联编号和校验指纹只能放在折叠的“追溯信息”区域。

使用核心辅助器生成单项审阅页：

```bash
python3 scripts/workflow_cli.py render <内部数据文件> --output <审阅页.html>
```

使用以下命令生成整轮或整账号的人工审计报告：

```bash
python3 scripts/workflow_cli.py audit-report --root <工作区> --output <人工审计报告.html>
```

执行器生成 HTML 后，应在最终回复中只提供 HTML 路径和一句业务摘要，不附带机器数据文件。
