# 运行时能力契约

本工作流不假定内容负责人使用某一个 Agent 产品。Skill 名称、安装目录和工具名称不是能力证据；只使用当前运行时已展示、已授权且已核对输入输出契约的能力。

## 启动与授权确认前的发现顺序

1. 读取当前 Agent 显式提供的 Skill、工具或能力列表。
2. 逐项核对是否具有本地 JSON 读写、追加式审计、人工批准、网页研究、登录态平台操作、原生生图和指标采集能力。
3. 记录实际 `capability_id`、能力信息来源、数据处理边界、返回形式和已知限制。不根据产品品牌猜测工具名。
4. 无法确认的项在内部保持未确定；如果会改变实施路径，用业务语言向内容负责人说明受影响的动作并请求补充信息。
5. 将快照写入内部任务记录，再进入“启动与授权确认”。

## 执行模式

| 模式 | 最低条件 | 可以声称的结果 |
|---|---|---|
| 完整执行 | 本地机器数据读写、追加审计和人工确认均可用 | 可运行完整可追溯闭环；其他能力仍按快照降级 |
| 人机协作执行 | 本地机器数据读写和人工确认可用，但部分自动化能力缺失 | 使用结构化导入或人工交接完成步骤，明确标记手动节点 |
| 仅生成方案 | 只能生成方案或交接包 | 只能声称方案已生成，不得声称工作流已执行或已闭环 |

执行方式尚未确定时不能完成启动确认。执行过程中如能力变化，内部校验指纹会改变，原启动确认自动失效并需要重新确认。

内部仍使用 `full`、`assisted`、`document_only` 和 `undetermined`，但人工提问和 HTML 必须使用上表中文名称。

## 原生生图路由

1. 只在 `native_image_generation.status=available` 时调用当前运行时展示的原生生图能力。
2. 必须确认 `processing_boundary=local|external`；保持 `unknown` 时不执行。“原生工具”不等于“本地处理”。
3. 在 Codex 中，仅当当前能力列表确实包含 `imagegen` 或等价原生生图能力时才使用；其他 Agent 使用各自已展示的原生能力。
4. 工作流包只产生 `image_job` JSON 交接件，不内置图片接口 SDK、密钥、端点或 HTTP 请求。
5. 原生能力若只返回会话附件而不是本地文件，将任务标记为 `generated_pending_export`；导出、验证并计算哈希后才能成为发布素材。
6. 原生生图能力不可用时，可用 `render_text_card.py` 在本地生成文字卡，或保留未执行的 `image_job` 供人工处理；不得声称图片已生成。

## 引用图和外部处理

原生生图仍可能在运行时边界外处理图片。使用引用图前必须同时满足：

- G0 `data_scope.external_processing` 已列出实际 `capability_id`、用途和数据类别；
- 引用素材的 `external_processing_approved=true`；
- 权利、个人数据和敏感信息检查已完成；
- 能力快照明确支持引用图。

任一条件不满足时，改用无引用图生成、本地文字卡或人工交付。
