# 小红书账号定位

内部为一个明确账号生成版本化定位记录。遵守 [数据契约](../xhs-workflow/references/data-contracts.md)，不得写入全局共享定位或覆盖其他账号。

面向内容负责人的所有提问和交付必须遵守 [人工交互与审阅规范](../xhs-workflow/references/human-interface.md)：使用其当前语言，把内部定位状态翻译成“定位探索中”“阶段性收敛”“当前范围内稳定”或“重新检验中”，只交付 HTML 审阅页，不展示原始 JSON。定位的证据链与门禁遵守 [定位生长闭环](../xhs-workflow/references/positioning-loop.md)。

## 前置条件

1. 内部要求明确的工作区、账号、本轮任务和已确认的账号运营策略路径；策略中的创作者方向必须已完成确认。
2. 校验任务与策略属于同一账号，并确认启动授权仍有效。
3. 修订定位时要求旧版本的明确路径，以及已确认的后续战略或评估上一版定位的真实复盘；引用实验时还要求有效 G6。不得用“最新定位”猜测。
4. 缺少会实质改变定位的信息时，请内容负责人确认；不得填入示例身份或推测个人经历。

## 工作流

1. 先诊断当前任务属于首次建立、定位基础不清、内容兑现不稳定、受众错配或证据不足，记录依据、其他可能解释与建议动作。内容兑现不稳定或证据不足时，不得直接把问题改写成“修订定位”。
2. 收集真实经历、可持续能力、目标、问题空间、目标人群、差异化证据、创作者生产成本、明确不做事项、可用内容形式和隐私边界。主赛道仍不明确时记录未知，不用完整文案掩盖证据缺口。
3. 把陈述分成已确认事实、创作者选择、定位假设和未知问题。按 [references/trial-positioning.md](references/trial-positioning.md) 建立稳定核心、开放问题、反向边界、可观察推论、反驳信号与验证计划；内部值不得出现在人工提问中。
4. 将已确认的创作者方向投射为本账号的角色、当下价值、未来价值、关系表达、信任机制、内容引擎、记忆资产和商业连接；存在冲突时显式记录，不静默改写创作者方向。
5. 如获授权，按 [references/competitor-research.md](references/competitor-research.md) 研究公开竞品；工具不可用时标注缺口，不生成虚假账号或指标。
6. 按 [references/persona-schema.md](references/persona-schema.md) 形成定位。每个假设独立记录组成部分、成熟度、把握度、范围、正反证据和复核时间；每个内容支柱显式关联受众分组、受众任务、交付价值、信任证据职责、记忆资产、商业连接、定位假设和表达边界，不强制支柱数量。非首版同时写入修订谱系、复盘和已批准实验引用。
7. 内部写入账号定位机器文件并标记为待人工确认；路径使用：
   `artifacts/<account_id>/persona/<artifact_id>.json`。
8. 运行核心辅助器校验并生成中文 HTML 审阅页。
9. 展示定位问题判断、创作者方向落地、稳定核心、开放问题、反向边界、与上一版的差异和证据，请内容负责人完成“账号定位确认”；探索阶段的确认只批准搜索空间和验证边界。
10. 确认通过后登记到本轮任务。旧版本保留并标记为已被新版本替代，不得静默覆盖。

## 质量规则

- 定位陈述必须能指出受众、价值和差异，不使用空泛标签；未知项允许保持未知，不能为追求完整而虚构答案。
- `credentials`、案例和成就必须有用户输入或可核对来源。
- 竞品信息只用于观察空位和表达模式，不复制文案、视觉或身份。
- persona 只提供创作约束，不替代本轮明确输入。
- persona 不重新发明创作者方向；如账号落地与方向冲突，先展示冲突并请求策略层决定。
- 定位修订前必须区分“定位基础错误”与“内容没有稳定兑现既定价值”。
- 非首版定位不接受断链修订：只有运营者新想法、不存在的引用、未评估上一版的复盘或未批准实验均不能通过 G1。
- `mode=validated` 只表示声明范围内阶段性稳定。升级必须由跨内容复盘、有效曝光、内容兑现、受众市场镜像、创作者适配和反向证据共同支持，并建立新版本、重新进行账号定位确认。
- 定位变化时同时提出昵称、简介、置顶内容、系列名称、评论回应和旧内容预期的迁移动作；版本号本身不能完成受众认知迁移。
- 不采集与定位无关的个人敏感信息。

## 输出

- 机器层：通过校验的内部账号定位文件，不直接交付给内容负责人。
- 人工层：中文可视化 HTML，包含定位问题判断、创作者方向落地、定位生长状态、稳定核心、开放问题、内容支柱映射、逐项假设、正反证据、风险、版本差异和决定区。
- 审计层：内部保存确认、校验指纹、版本关系和登记事件；人工查看时统一渲染为 HTML。
