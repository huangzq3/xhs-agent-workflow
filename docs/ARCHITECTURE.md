# 架构说明

## 设计目标

小红书 IP 运营工作流把方向、定位、内容、发布和数据放进同一条可追溯链路，同时保留内容负责人对高影响决定的控制权。运行环境可以更换，但每轮只能使用已经展示、已经授权并完成输入输出核对的能力。

## 两层事实

工作流分离两类产物：

1. **机器层**：JSON artifact、状态和追加式审计事件，是 Skill 之间的事实源。
2. **人工层**：由机器事实确定性生成的中文 HTML，用于内容负责人阅读、判断和确认。

HTML 不参与下游自动化解析。机器层也不直接粘贴给内容负责人。业务内容发生变化后，旧审阅页和依赖旧 payload 指纹的确认随之失效。

## 创作者方向与账号定位

```text
创作者方向
  ├─ 90 天主目标与商业去向
  ├─ 当下价值、未来价值与关系姿态
  ├─ 信任引擎、内容引擎与记忆资产
  └─ 红线、证据、假设与未知
        ↓ 已确认方向在单个账号中的投射
账号定位搜索空间
  ├─ 先诊断定位问题类型
  ├─ 稳定核心、开放问题与反向边界
  ├─ 逐项定位假设与成熟度
  └─ 内容支柱到受众任务、证据职责、记忆资产和假设的映射
        ↓ positioning_trace
选题 → 内容 → 数据快照 → 逐项复盘 → 探索或受控实验
        ↓ 跨内容、多证据流、反证与市场镜像
当前声明范围内阶段性稳定，或重新检验
```

创作者方向属于账号策略的上位约束，不另建一个与账号策略竞争的平行 IP 档案。persona 不自行发明长期方向，而是先诊断定位问题，再把已经确认的方向落到本账号。账号定位不是永久身份定义，而是带适用范围和复核时间的搜索状态。

出现内容表现问题时，复盘必须先区分：

- 定位基础是否不清；
- 内容是否没有兑现已确认定位；
- 受众是否错配；
- 证据是否不足。

只有证据支持方向或定位变化时，系统才形成待人工确认的修订建议；不会静默覆盖当前版本。非首版 persona 必须回指已确认上一版，并证明修订来自后续已确认战略，或评估上一版的复盘与已批准实验。

选题和稿件用同一份 `positioning_trace` 锁定本篇服务的受众任务、价值、证据职责、记忆资产与定位假设。复盘必须逐项回应这些假设，并同时记录受众共鸣、内容兑现、平台分发、创作者适配、业务适配和受众市场镜像。稳定定位的 G1 会反查真实上一版、复盘、至少两篇有效定稿内容和数据快照，不接受装饰性的引用字符串。

## 八个 Skill

| Skill | 业务职责 |
|---|---|
| `xhs-workflow` | 启动、能力与数据边界、创作者方向、账号策略、库存、人工确认、审计和 HTML 渲染 |
| `xhs-persona` | 定位问题诊断、方向的账号投射、定位搜索空间、逐项假设、阶段性收敛与重新检验 |
| `xhs-topic-report` | 证据化选题研究、定位探针设计、竞品拆解和候选比较 |
| `xhs-writer` | 按已确认定位追踪完成图文、视频或纯文字创作，管理素材权利和原生生图交接 |
| `article-audit` | 在全新只读上下文中独立审计文章，不改稿也不代替人工批准 |
| `xhs-publish` | 发布规则、最终预览、立即或定时发布、一次尝试和实际上线结果核对 |
| `xhs-content-review` | 从实际上线时间起算，逐项复盘定位假设、五路证据、市场镜像、信任和长尾表现 |
| `xhs-iterate` | 定位探索探针或受控优化，以及定位或运营策略修订建议 |

## 门禁

| 门禁 | 决定 |
|---|---|
| G0 | 启动、能力、数据来源和外部处理范围 |
| G1 | 创作者方向、账号策略与定位 |
| G2 | 选题进入创作 |
| G3 | 内容定稿；必须先完成有效的独立文章审计 |
| G4 | 一次发布或排期尝试 |
| G5 | 发布后修改、删除或其他高影响处理 |
| G6 | 复盘判断和下一轮实验 |

门禁记录绑定当前 payload 指纹。影响决定的内容变化后，旧确认不再有效。
